# Signs Studio Undo and Redo

A green Undo button with a curved left arrow sits above the right-hand preview. Redo with a curved right arrow appears after Undo. The toolbar remains outside the authoritative print document. Each history entry stores the complete design, including text zone IDs/content/font/formatting/geometry, background preview and print URLs, orientation, QR settings and messages. Up to 100 actions are retained in memory per account/event/design while the editor remains mounted. New edits discard the redo branch. Initialization and external reload changes establish a baseline rather than an undoable edit.

Continuous typing and slider updates are grouped; focus/pointer boundaries separate actions. Preview gestures already commit on pointer-up and are recorded as discrete actions. Undo/Redo use the existing debounced save queue and feed the same preview/export state. Existing saved designs and new designs use the same history path; identity fields are never restored from another event's snapshot.

Validation: state-machine and hook tests cover complete deletion restoration, multiple ordered actions, grouping, separate gestures, branching, initialization and event switching, with persistence. A real isolated browser using synthetic intercepted data verified deletion, Undo, Redo and drag-gesture Undo. The restored A3 preview and actual rendered PDF compared with zero different pixels. The toolbar was visually inspected above the right preview and outside the export document at desktop and tablet sizes.

The repeated dashboard error was a Vite memory-cache issue: the served Dashboard module was empty while the saved source was intact, causing React Lazy to resolve an undefined component. Restarting only the owned localhost Vite process restored it. The watcher now waits for source writes to stabilize before invalidation; Run Sheet and Signs Studio subsequently rendered without that error, and the user confirmed the dashboard opens.

Placement correction: buttons are centered as a group over the actual right preview with a 12px gap. A real browser geometry check found less than 0.01px center difference. Invitations & Cards now uses the same bounded snapshot engine for each account/event/artwork, with full document fields, the existing serialized autosave, separate gestures, grouped text editing and redo branching. Names/identities/timestamps are outside the document history. Name Place Cards was not changed. Real browser deletion/Undo/Redo/gesture restoration passed and its restored A5 PDF also matched the preview with zero different pixels. Both toolbars stay outside the printable document.
