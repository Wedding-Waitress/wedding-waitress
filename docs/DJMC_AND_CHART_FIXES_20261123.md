# DJ/MC Undo and Full Seating Chart sorting

DJ/MC default text fields previously committed on blur, so the top Undo saw a whole edit. They now commit each input change through the existing optimistic update and 300ms database debounce. Five typed characters followed by five top Undo restores were tested as four, three, two, one and zero characters, with each restore saved/refreshed. Blur adds no duplicate action. Existing Run Sheet and Signs Studio history semantics are unchanged.

Full Seating Chart uses stable table identity and canonical numeric metadata, with a strict numeric/default Table N name fallback for older tables without table_no. Previously these tables all compared as zero, globally alphabetizing regular guests. Head tables remain first, custom tables retain their own grouping, numbered tables sort numerically, and unassigned entries are last. Names sort within each distinct table. The saved tableNo preference value is unchanged; only its displayed label is Table Number \ Names. The sorted list feeds the existing preview pagination and both PDF export paths; no guest or table data is rewritten. Tests include both saved-data patterns, numeric strings, custom names, head/null numbers, event scope, unchanged first/last-name modes and multi-page pagination.

Instant DJ/MC Undo follow-up: eligible text snapshots now apply synchronously without setting the Undo busy state, changing component keys or refetching the questionnaire. They reuse the 300ms item/section autosave, now serialized to keep older slow saves from overwriting a later Undo. Pending/in-flight writes suppress realtime echoes. Tests hold an old network save open, apply five local Undos immediately, then verify the newest value persists last. Structural edits and recordings retain the complete recovery path. Run Sheet is unchanged.
